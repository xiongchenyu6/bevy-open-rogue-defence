# 已持有装备选择的视觉确认

自然 C6 路线失败时，三次不同图标点击后详情都保持 Hardened Plate。[原失败证据](../inventory-chapter6-2026-11-06/README.md) 不变。此前空 Forge 的操作系统输入以及受控原生 Item 鼠标消息都能正常切换，不能据此断言零持续时间点击就是根因，也没有改动生产选择逻辑。

本轮只为未来的公开界面逐项检查添加小型确认步骤，避免输入尚未产生可见选择时立即读取旧详情。它确认卡片的**视觉选择状态，不识别装备身份**。

## 先测量实际图片

[初始测量](measurement.json) 覆盖 14 个现有桌面 PNG 路径；[扩展测量](measurement-expanded.json) 覆盖 48 个路径、240 个取样点，包括重复归档与多轮同场景捕获，不代表 48 次独立操作系统验收。采样位置是现有 96 像素装备卡中心减去 `(45,45)` 的内侧留白。

实际可见装备卡的选中留白 RGB 为 `(56,49,26)`，未选中为 `(9,14,17)`。C6 三张失败检查截图中，前三个位置始终是“未选中、选中、未选中”；没有把错误的第一/第三张判为选中。其他颜色来自关闭后的战斗画面或打开前的过渡画面，不能视为选择确认。

## 助手行为

Forge 与 EquipmentPolicy 共享同一个已持有装备检查函数：

1. 从实际截图确认装备标题、可解析持有数量、索引有效和卡片留白颜色已知。仅支持现有三列四行的 12 张完整可见卡；未知界面或越界不发送输入。
2. 对该可见卡中心只发一次 mouseDown，在当前访问剩余时间与十秒的较小期限内，等待新截图中该卡留白变为精确选中色。未知颜色或超时失败，finally 总是尝试 mouseUp，无重试点击。
3. 释放后另拍新图，用原严格选中标题解析读取真实身份；原全部已持有名称唯一性、数量及与实际购买集合完全一致的检查不变。市场扣款、材料与按钮检查不变。

没有根据预期目录猜名称，没有将留白颜色当成装备身份，没有增加通用图像识别或输入框架，也没有修改现有不可变包/已运行助手快照。

## 验证与未验证部分

[完整隔离 Docker 默认 discover 日志](tests.log)：**89 项通过、无跳过**，85.305 秒；[命令与返回码](result.json) 为 0。新增五个测试覆盖真实 C6 截图的第一/中间/第三卡正反例，原生第一/最后选中卡与关闭后未知颜色拒绝，以及一次按下、等待延迟视觉确认、释放、未知标题、无效索引、未知像素与超时控制流。[源码哈希](source-hashes.json) 标识本轮版本。

本轮没有启动完整自然合成或 C6 重试，也没有通过操作系统实际执行新增视觉确认函数。真实 PNG 测量与控制流测试支持该助手改动；是否能使后续自然路线完成仍待单独真实运行验收。原 C6 失败保持失败，不因新增测试变为通过。
