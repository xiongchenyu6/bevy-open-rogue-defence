## 隔离复测

使用相同不可变 495 包、断网 Docker、只读包及助手快照。新隔离状态只复制真实积累的初始 campaign.save（SHA-256 `da5bf0a9ca3f4032a265425f9989bda292d8c0c2622848157df6d2c0223ba825`），没有装备、库存、战功或教程偏好注入。实际跳过教程、选择基础 Storm Savant 后，打开空背包测试相同 Close 按钮。

最初诊断脚本误匹配合并的多个英雄名，未能进入战斗；[失败](probe-startup-failure/runtime.log) 单独保留，未计为关闭测试。之后使用生产驱动相同的英雄名称精确过滤。

[第一轮原型](prototype/result.json) 的三次关闭成功，但全屏 OCR 较慢，未记录按下和释放的准确时间，不能拿总耗时证明十秒按键预算。最终版本只对同一原始截图的装备标题栏裁剪做 OCR，恢复真实屏幕坐标；每轮仍保留完整截图及释放后的完整画面检查。

## 助手改动边界

共享的装备关闭函数用于未来 Forge 与 EquipmentPolicy 路线：必须先观察到装备标题、可解析数量和实际标题栏 Close；一次按下，在有限期限内等待同图上的装备标题与 Close 均消失，然后总是释放。观察返回时再次检查期限，释放后保留原完整截图的严格关闭断言。EquipmentPolicy 使用当前访问剩余预算与十秒的较小值。当前已运行的 C6 助手快照未修改。

没有新增游戏逻辑或通用输入框架，没有修饰原失败状态。本轮空背包测试不证明持有装备时的自然路线已通过；完整自然合成和同状态重启仍待后续授权运行。

完整隔离 Docker Python 默认 discover 套件：[最终日志](tests/tests.log) **84 项通过、无跳过**，79.723 秒；[返回码与完整命令](tests/result.json) 为 0。首轮测试时钟桩在 finally 记录时间时耗尽，修正桩后重跑完整套件；原日志保留，生产代码未因此放宽。四个控制流测试覆盖一次按下/释放、延迟关闭、未知界面/缺失按钮/越界按钮拒绝输入、超时与读取/派发异常仍释放。
