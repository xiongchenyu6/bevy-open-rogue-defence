# Real-window frame-time probe

`perf_probe` runs the production windowed app and normal render/present path. It requests no screenshots or GPU readback. Render-schedule hooks check that a swapchain texture existed before `render_system` and was consumed by its present call before recording a monotonic timestamp. These intervals measure application present-call cadence, not GPU execution timestamps or compositor-displayed frames. FIFO pacing also limits throughput interpretation. `ROGUE_PERF_PRESENT_MODE=immediate` enables a diagnostic control; the default remains FIFO and the production game settings are unchanged.

The controlled fixture places the hero at `(-2,0,0)` and injects 180 stationary targets using all 12 imported enemy models in the nearby lane. Targets have `1e7` HP, rather than `1e9`, so ordinary damage does not disappear under excessive f32 spacing. The first six skills are rank 3 (Arc Chain, Ember Arrow, Frost Lance, Tidal Fan, Bone Sentry, Static Seal), virtual elapsed starts at 720 seconds, and hero/gate health is protected. Normal basic attacks, skill costs/cadence, automatic ultimate and animation systems run at 1× or 32×; effects are not manually injected. Audio is muted. This is a controlled workload, not earned progression, audiovisual validation or a packaged campaign benchmark.

`SpawnDirector.enabled=false` already disables ordinary/elite/due boss spawning, including when 32× crosses boss thresholds. Autoplay is absent, automatic bond draws/trials are disabled and recruitment milestones marked claimed. Camps require player requests and are not triggered. Sampling rejects unexpected enemy counts, retired fixture targets, paused/finished gameplay or a changed virtual speed.

Readiness requires the production `AssetReadiness` flag plus recursive loading of the selected hero, all enemy models, Bone Sentry, current environment world assets, font and equipment atlas. All 180 specifically tagged fixture roots must have children and a `WorldInstance` confirmed ready by Bevy’s `WorldInstanceSpawner` before warmup begins. Startup, warmup and sampling present frames are counted separately. This is asset/scene readiness, not a guarantee that all shader compilation or GPU uploads have completed; the requested warmup remains necessary.

Measurement also requires actual target HP loss, an active (positive-lifetime) projectile and at least one production skill cast during the sample. JSON records per-skill cast deltas for the six selected skills. A summon already at its cap may legitimately have no new casts during sampling. Entity CSV snapshots (1Hz) record total entities/enemies, active projectiles, mesh components, virtual elapsed, paused/finished flags, tagged imported roots, actual virtual speed, cumulative skill casts and summons. Mesh counts include pooled/hidden components; they are not draw-call counts. The projectile peak is the peak of 1Hz sample snapshots, not a frame-exact maximum.

Every sampled present adds one interval to a preallocated buffer. JSON records adapter/driver/backend, physical surface size, FIFO presentation and frame latency, seed, readiness, wall times, present counts and nearest-rank p50/p95/p99/max. CSV preserves each interval. The requested window is 1280×720 logical; recorded physical surface dimensions are authoritative on scaled displays.

Build with `nix develop --command cargo build --locked --release --bin perf_probe -j2`. Run `perf_probe SPEED WARMUP_SECONDS SAMPLE_SECONDS OUTPUT_PREFIX`, with explicit `BEVY_ASSET_ROOT` pointing to the repository and isolated `XDG_CONFIG_HOME`, `XDG_RUNTIME_DIR`, `ROGUE_CAMPAIGN_SAVE`, `ROGUE_AUDIO_SAVE` and `ROGUE_TUTORIAL_SAVE` paths. Record `ROGUE_COMMANDER_SEED`, `ROGUE_PERF_PURPOSE`, `ROGUE_PERF_CONCURRENT_WORKLOAD` and `ROGUE_PERF_BUILD_PROFILE`. An unspecified build is labeled unrecorded rather than guessed from debug assertions. Do not use personal saves or collect baseline timings while builds or other rendering jobs run. Startup has a 60-second budget in addition to the requested warmup/sample lengths; use a slightly larger external process timeout too.

Current optimized runs are archived in [the performance evidence](verification/window-performance-2026-11-05/README.md), with raw present intervals, workload snapshots and source/binary hashes. Each final case uses 10 seconds of warmup and 30 seconds of sampling. On the actual 1920×1080 Wayland window, the 1×/32× P95 present intervals were 11.25/11.47ms. The 1280×720 Xvfb FIFO cases were around 36ms; its Immediate control remained around 35.64ms. Different display paths and physical dimensions prevent treating that gap as a single-variable causal result or using Xvfb timings as a physical-playability estimate.

The user-CPU profile highlights transform propagation and animation work in the instrumented Xvfb case. CPU sample percentages do not translate directly into wall-time savings. The test uses local Nix-linked optimized binaries; these are not portable Steam Runtime release candidates. Longer campaign runs, other hardware, fully evolved builds and Steam Deck remain separate gates.
