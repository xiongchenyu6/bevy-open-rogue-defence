# Damage number readability

Dense combat labels previously separated only hits on the same target. Neighboring enemies still produced overlapping numbers, amplified by critical labels reaching an 84-pixel peak size.

The current change uses 24-pixel ordinary labels and 32-pixel critical labels, with respective peak scales 1.12 and 1.25. Criticals retain gold color and the exclamation mark. A single placement pass considers all active labels, ordered by critical status, recency and stable entity identity. It reserves estimated peak glyph rectangles and searches 35 nearby positions, constraining the resulting rectangle to the usable viewport region. If no clear position exists, it chooses the least-overlapping nearby candidate rather than suppressing the amount.

Damage arithmetic, same-target aggregation window, element colors, lifetime, pool capacity and formatting are unchanged. Existing mixed normal/critical aggregation semantics remain: any critical hit marks the combined label critical. This does not mean every hit included in that sum was critical.

Two pure placement tests cover coincident labels, viewport bounds and deterministic packed fallback. They do not prove actual font bounds, HUD clearance, temporal stability or perfect packing in crowded viewports. The native audit uses real mixed-skill damage in English and Simplified Chinese at 1280×720, 667×375 and 390×844. Full library tests passed 595 cases, with 0 failures and 1 existing ignored test; strict all-target Clippy, formatting and both binaries built successfully. Six native NVIDIA cases completed 4,080 frames with actual damage/effect checks. Root inspected all 12 new screenshots and compared desktop results with the preceding baseline. Desktop and portrait labels overlap less and criticals remain recognizable; these static images cannot establish temporal stability or exact association with every target. Compact landscape still has camp labels and upgrade notifications over the battle/controls. This broader layout failure remains unfinished, and crowded fallback does not guarantee non-overlap.

The first native waiter exited prematurely during the long build and did not run screenshots; after authoritative build completion, the waiter was corrected to distinguish actual terminal states from a transient observation failure. The successful second run is the evidence cited here. [Raw screenshots, logs and source hash](verification/damage-readability-2026-10-08/verification.json) preserve the audit.
