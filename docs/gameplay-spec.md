# Rogue Commander 玩法权威规格

> 版本：首版（N1）
> 状态：实现基线
> 原则：高还原 25 分钟防守、技能与羁绊双抽取、爬塔、黑市和流派构筑的节奏；角色、名称、美术、数值与世界观保持原创。

本文是首版玩法实现与平衡的权威来源。代码、测试和其他文档与本文冲突时，以本文为准；需要改变规则时，应先更新本文。

### 规格标记

- **【公开确认】**：可由公开地图资料或玩家视频直接确认的原作结构，实现时不得擅自改成另一种循环。
- **【首版设计】**：为补足资料缺口而制定的原创名称、内容、公式和数值，是当前实现基线。
- **【未知可调】**：原作精确行为或数值尚无可靠公开证据；先按首版设计实现，获得新证据或试玩数据后可调整。

除明确标为【公开确认】的结构外，本文所有原创名称、生命、伤害、价格、概率、时间细节与奖励量均属于【首版设计】。第15节集中记录仍属【未知可调】的项目。

## 1. 核心规则

- **【公开确认】横向守门：** 战场左侧是城门，常规敌人从右侧生成并向左推进。不得实现成围绕中央核心的四面刷怪。
- **【公开确认】主流程：** 主战阶段持续到 25:00，Boss 在 5:00、10:00、15:00、20:00、25:00 出现。公开实战在击败最终Boss后提示约10秒进入存档挑战，随后进入顶栏约598秒、含多个挑战目标的存档区。
- **【首版设计】终局改编：** 本项目暂不复刻多人／局外存档区，改为最终Boss后立即进入60秒单机“战果刻印”输出验证，再结算本局。
- **【公开确认】顶栏资源：** 战斗顶栏持续显示金币、杀敌、木材，黑市使用杀敌。
- **【公开确认】快捷键：** `Q` 爬塔挑战、`W` 金币挑战、`F` 羁绊、`G` 技能、`F4` 清除当前挑战怪。
- **【公开确认】羁绊容器：** 未完成羁绊最多占用7个槽位；羁绊完成后被吞噬为永久局内效果，并释放其槽位。
- **【公开确认】黑市：** 商品以可用杀敌数购买，而不是金币或木材。
- **【首版设计】自动战斗：** 英雄自动普通攻击并自动施放已装备技能；玩家控制移动、闪避和英雄终极技。
- **【首版设计】守门失败：** 左侧城门初始耐久1000。敌人抵达后消失并造成固定突破伤害，耐久归零即失败。
- **【首版设计】英雄死亡：** 8秒后复活，城门额外损失80；每次死亡使本局后续复活时间增加3秒。
- **【公开确认】开局引导样本：** 公开实战约00:04首次显示`G`技能面板、约00:12首次显示`F`羁绊面板；开局任务同时赠送资源，不能据此反推原作实际抽取价格。
- **【首版设计】抽取时机：** 本项目在0:04存入首次免费技能三选一，在0:12存入首次免费羁绊三选一；之后分别花金币和木材抽取。
- **【首版设计】杀敌记账：** 顶栏显示可用于黑市的 `kill_credit`；不可消费的累计击杀另存为 `total_kills`，供战绩与成就使用。
- **【公开确认】原作不停表：** 公开实战中的选卡、羁绊替换、奇遇和黑市浮层打开时，背景敌人、投射物、倒计时与自动挑战仍继续运行。
- **【首版设计】手机可读性暂停：** 本项目打开技能、羁绊或黑市时暂停背景战斗；这是易用性改编，不是原作行为。Q/W挑战期间主战场继续运行。

### 1.1 战场与镜头

- **【公开确认】** 屏幕推进方向固定为右到左，入口与视觉构图不可镜像。
- **【首版设计】** 世界坐标中城门模型位于 `x = -14.8`，常规出生带位于 `x ∈ [15.3, 16.4]`；地面横向使用 `x`，纵深使用 `z`。英雄通常在城门与出生带之间活动，遁地单位可从左侧特殊出生带出现。
- **【首版设计】** 敌人使用沿横轴向左的简单 steering，局部绕开友军；无需网格寻路。
- **【首版设计】** 自动攻击优先级依次为冲城单位、距城门最近单位、距英雄最近单位。
- **【首版设计】** 静态倾斜镜头必须同时看见左门、英雄与右侧出怪预警区。

### 1.2 HUD 与输入

- **【公开确认】** 顶栏至少包含 `金币`、`杀敌`、`木材`；首版在同一栏追加城门耐久、计时与Boss血条。
- **【首版设计】** 頂欄順序為：城門耐久｜金幣｜可用殺敵｜木材｜時間／波次；不可消費的累計擊殺在結算面板另行顯示。
- **【首版设计】** 手机端左侧为虚拟摇杆，右侧为闪避和终极技；`Q/W/F/G` 映射成带文字与图标的大按钮。
- **【首版设计】** 手机端按下“清除挑战”等同 `F4`；所有触控目标不得小于48 dp。
- **【开发工具】** `F7`开关生成器，`Tab`切换普通怪／精英／Boss，`[`／`]`（或数字键盘4／6）选择目标；精英模式用`-`／`=`（或2／8）选择词缀，`Enter`生成。暂停或结算期间禁止生成。

## 2. 战斗与属性公式

三项属性为力量、敏捷、智力。英雄主属性额外计入攻击伤害。

```text
最大生命   = 英雄基础生命 + 力量 × 14
最大能量   = 英雄基础能量 + 智力 × 8
攻击伤害   = 武器基础伤害 + 主属性
法术强度   = 20 + 智力 × 2
召唤强度   = 法术强度 × 0.7 + 攻击伤害 × 0.5
物理承伤率 = 100 / (100 + 5 × max(护甲, 0))
魔法承伤率 = 1 - 魔抗
技能等级值 = R = 技能等级 - 1；正常抽取 R ∈ [0, 4]，登临冠例外可达 R = 5
```

- N1 英雄默认武器基础伤害20、护甲0、魔抗10%，暴击率5%，暴击伤害175%。
- 默认闪避冷却 4.5 秒、无敌 0.22 秒、移动距离 3.2 米。
- 一般技能控制对普通敌人全额生效、对精英持续时间×0.5、对Boss持续时间×0.2；英雄专属被动／终极技表中的固定Boss时长为明确例外。Boss仍完全免疫牵引等强制位移。
- 同名持续伤害刷新持续时间并累加层数，不创建独立计时器。
- 伤害至少为 1。对 Boss 的百分比生命伤害每次不得超过其最大生命的 0.5%。

## 3. Rust 数据骨架

数据定义不得保存闭包或系统函数指针。所有关联通过稳定字符串 ID 完成，便于后续迁移至 RON。

```rust
type Id = &'static str;

#[derive(Clone, Copy)]
struct ScaledValue {
    base: f32,
    per_rank: f32,
    attack_ratio: f32,
    spell_ratio: f32,
    summon_ratio: f32,
}

struct SkillDef {
    id: Id,
    rarity: Rarity,
    tags: &'static [Tag],
    cooldown_secs: f32,
    effect: SkillEffect,
    rank_mods: &'static [RankMod],
}

struct BondDef {
    id: Id,
    favored_tags: &'static [Tag],
    tiers: [BondTier; 3], // 【首版设计】thresholds are 2, 4, 6
}

struct BondInventory {
    developing: Vec<BondProgress>, // hard cap: 7 distinct unfinished bonds
    completed: Vec<Id>,            // swallowed effects; no longer occupy slots
}

struct Wallet {
    gold: u32,
    kill_credit: u32, // displayed as “杀敌” and spent by the black market
    lumber: u32,
    total_kills: u32, // statistics only; never decreases
}

struct HeroDef {
    id: Id,
    primary: Attribute,
    base_stats: Stats,
    growth: Stats,
    starting_skill: Id,
    passive: PassiveDef,
    ultimate: UltimateDef,
}

struct EnemyDef {
    id: Id,
    hp: f32,
    damage: f32,
    armor: f32,
    speed: f32,
    bounty: u16,
    kill_credit: u16,
    xp: u16,
    breach_damage: u16,
    behavior: EnemyBehavior,
}

enum ChallengeKind {
    Tower { floor: u8 },
    Gold { tier: u8 },
}

struct ActiveChallenge {
    kind: ChallengeKind,
    remaining_secs: f32,
    spawned_entities: Vec<Entity>,
}

struct ChallengeRegistry {
    active: Vec<ActiveChallenge>, // at most one Tower and one Gold challenge
}

struct WaveDef {
    minute: u8,
    count: u16,
    hp_mult: f32,
    damage_mult: f32,
    mix: &'static [(Id, u8)],
    checkpoint_boss: Option<Id>,
}
```

`SkillEffect` 首版只允许 `Projectile`、`Nova`、`GroundZone`、`AttackProc`、`Orbit`、`Summon`、`Mark`、`Echo`、`Revive`。核心标签为：

```text
Attack, Spell, Summon, Storm, Flame, Frost, Tide,
Physical, Arcane, Qi, Guard, Fortune, Control
```

## 4. 成长、抽取与经济

### 4.1 等级

```text
升至下一等级所需经验 = 60 + 18 × (当前等级 - 1)
```

- 初始等级 1，上限 30。
- 升级自动增加英雄成长属性，不弹出卡牌界面。
- 等级 5、10、15、20、25 各赠送一次免费技能抽取。

### 4.2 技能抽取

```text
付费技能抽取价格 = min(80 + 已付费抽取次数 × 15, 260) 金币
```

- 技能槽 6 个，正常抽取最高 5 级；登临冠可把当前最高级技能立即提高1级、但不超过6级。
- 获得已有技能会使其升 1 级；满级技能从抽取池移除。
- 6槽占满后，选项只会出现已有技能升级；首版没有技能替换面板。
- 史诗技能在 12:00 后进入卡池，一组三选一中最多出现一张。
- 单次三选一不得连续两次完全没有当前英雄、技能或羁绊所偏好的标签。

### 4.3 羁绊抽取

**【公开确认】** 羁绊使用独立容器，最多同时容纳7种未完成羁绊；完成羁绊会被吞噬为永久局内效果并释放槽位。

**【首版设计】** 付费木材价格依次为：

```text
10, 10, 12, 12, 14, 14, 16, 16, 18, 18, 20, 20, ...
```

- 每次选择使对应羁绊增加1点，2/4/6点触发三个层级。
- 权重为：已有羁绊 45%，英雄与技能匹配 35%，其余随机 20%。
- 第一次取得某羁绊时占用一个槽位；重复取得只增加其点数，不额外占槽。
- 第7个槽位占满后仍可能抽到新羁绊；选择新羁绊会进入7张当前羁绊替换面板，明确选定被替换者后才结算。放弃替换只补1次刷新，稍后继续不会重复扣款；自动游玩按最低进度、再按稳定ID替换。
- 羁绊达到6点时播放吞噬反馈，从 `developing` 移入 `completed`；其2/4/6层效果全部永久保留，且不再进入卡池。
- 已完成羁绊不计入7槽上限。首版不设已完成羁绊数量上限，但正常经济预期只能完成1–2套。

### 4.4 收入目标

- **【公开确认】** Q爬塔产出木材，W金币挑战产出金币，杀敌用于黑市。
- **【首版设计】** 金币用于G技能抽取，木材用于F羁绊抽取；普通波次同时提供少量金币。
- **【首版设计】** 被动金币：每秒2。
- **【首版设计】** 可用杀敌按敌人资料表结算：多数普通怪为1，岩背巨像与攻城投手为5；精英将该值乘8，五个检查点Boss依次为120/200/280/360/440。无奖励随从、分裂体和召唤体不重复提供杀敌。
- **【長局實測，待再平衡】** `0xA11CE` 在正常抽卡與自動W下以未花金幣59,320結束；6技能／30總等級後缺少後期金幣出口，原7000–7800目標未達成。
- **【長局實測，待再平衡】** 該局累計擊殺1,974，黑市逐代最多自動購買2件後剩餘可用殺敵964；原1450–1700目標偏低。
- **【長局實測，待再平衡】** Q推進至14層、持續F抽取後仍剩木材1,241；原290–330目標偏低，且不代表24層全部獎勵。
- **【長局實測，待再平衡】** 終局為30個技能等級、21點未完成羈絆、0套吞噬完成；玩法鏈可通關，但羈絆完成率與資源出口仍需六英雄長局校準。

### 4.5 三资源状态

```text
击杀常规敌人  -> 金币小额奖励 + 可用杀敌 +1或+5（精英再×8）
Q 爬塔        -> 木材 -> F 羁绊抽取
W 金币挑战    -> 金币 -> G 技能抽取
可用杀敌      -> 黑市购买与刷新
```

`kill_credit` 在黑市消费时减少；`total_kills` 只用于战绩、成就与复盘，不会减少。杀敌是否在原作中作为可扣除余额显示仍属【未知可调】，首版按此双字段实现，避免消费后丢失战绩。


## 14. 随机、性能与平衡约束

- 所有局内随机使用可记录种子；相同版本、英雄、难度和种子必须产生相同抽取与波次顺序。
- 桌面运行可用 `ROGUE_COMMANDER_SEED=0xA11CE cargo run` 固定种子；离屏捕捉将种子作为最后一个参数，支持十进制或 `0x` 十六进制。

```bash
cargo run --bin capture -- still screenshots/showcase.png 300 showcase 0xA11CE
cargo run --release --bin capture -- simulate screenshots/balance-25m.png 60000 balance 0xA11CE
```

- 普通波次同屏逻辑上限为130；敌人池全域活跃上限为160，并在最多256个保留场景根中划出226个普通槽与30个特殊槽，供Q/W、Boss、Boss召唤和Archive使用。退役敌人经过2.5个游戏秒隔离后才可重用；暂停不会推进隔离计时。
- 达到普通敌人上限后，最多延迟生成8秒；仍无空位时，把积压生成预算合并成一个等总生命、等总突破伤害、等奖励的强化敌人，不能直接丢弃压力。分裂怪无法整组取得外壳时也必须进入可恢复积压队列。
- 玩家召唤物共享20个硬上限。投射物保留256个可见mesh外壳；超出的有效攻击改用弹性、无mesh的逻辑外壳，仍参与移动、命中与伤害。短期命中特效池为128；伤害数字池为64，并在约0.12秒内合并同目标数字、满池时覆写最旧视觉。
- 所有上述实体统一由战斗池管理。画质下降只可合并数字、减少视觉外壳、粒子和阴影，不得改变实际敌人压力、命中或伤害数据；池指标必须分别报告逻辑总量、可见量、视觉降级与拒绝量。
