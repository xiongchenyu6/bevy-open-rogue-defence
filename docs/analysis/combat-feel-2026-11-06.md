# 攻击手感：两张参考的落地标准

参考来自用户 2026-11-06 提供的两张截图。截图说明设计方向，不能据此推断视频里的准确时长、音效或实现。

玩家应先看清出招，再在命中瞬间感到重量，最后看见短促收招。普通攻击保持克制；暴击、精英击杀和首领击杀逐级增强。八种表现不能每次一起触发，也不通过额外伤害、额外弹道冒充视觉反馈。

| 事件 | 主要反馈 | 限制 |
| --- | --- | --- |
| 普通近战 | 可读的蓄力、武器接触、局部受击闪色、短尾迹、收招 | 不持续震屏，不全屏闪白 |
| 普通远程 | 拉弓或施法准备、一条可辨弹道、目标接触点 | 单目标一次普攻不增加第二支装饰箭 |
| 暴击 | 更锋利的局部亮斑、少量碎片、更重的音色 | 同一轮齐射合并镜头冲量 |
| 精英击杀 | 短促停顿、定向碎片、较强音效 | 设冷却，不能被密集召唤攻击反复续满 |
| 首领击杀 | 最强一级停顿与震动、清晰死亡动作、奖励收束 | 恢复战斗速度；避免遮挡下一次选择 |
| 技能升级与进化 | 更大轮廓、不同结构和音色层次 | 基础武器保持朴素，成长后才逐级展开 |

## 已存在的实现与边界

- `src/game/basic_attacks.rs::swing_windup` 已按武器分别设接触阶段：剑 0.60、匕首 0.50、其余 0.42，乘实际受限动作窗口。这些是现有实现，不应统一改成同一接触点。
- `src/game/hit_feedback.rs` 已有局部受击、碎片、镜头冲量和重击杀停顿。普通命中不震屏；精英与首领击杀分别请求 0.055 与 0.16 秒停顿。存在实现不等于所有攻击都已完成原生视觉验收。
- 同一帧镜头冲量取最大值，避免多投射物相加；高速战斗跳过停顿。应保留这些可读性约束。
- 本轮近战尾迹透明衰减已有独立截图证明，见 `../verification/melee-trails-2026-11-06/`；该改动尚不在 d454 独立包中。

## 下一轮验收

固定同一场景、同一武器与攻击速度，连续记录蓄力前、接触前、接触帧、接触后、收招五个时刻，另录连续攻击。逐项核对武器接触与实际扣血、受击亮斑与音效时刻，不能只拿最亮的一张图证明手感。分别检查 1 倍与高速战斗，并核实表现变化没有增加攻击次数、伤害或随机数消耗。

当前文档是实现与验收基准，不宣称新反馈效果已经落地。完整视频、实际声音及持续高密度战斗仍须实测。
